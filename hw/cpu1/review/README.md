# cpu1 as pictures

A committed snapshot of the board, so it can be looked at without a KiCad
install. Everything here is generated:

    make review BOARD=cpu1

| File | What it is |
|---|---|
| `F_Cu.svg`, `In1_Cu.svg`, `In2_Cu.svg`, `B_Cu.svg` | One plot per copper layer. The layer list is read from the board rather than written down, for the same reason the gerber list is. |
| `assembly.svg` | Silkscreen over the fabrication layer: designators, courtyards, outline. |
| `top.png`, `bottom.png` | KiCad's raytracer. |
| `data.json` | Every footprint and every net, extracted from `build/design.json`. |
| `index.html` | The three above, arranged to be read. Also published at <https://claude.ai/artifact/3PVm7YgS6HqkqDAqNbpzrE>. |

## What these are not

**The renders are not a check on anything electrical.** No 3D model library is
installed in this environment, so parts appear as their bare land patterns, and
a footprint renders identically whether or not its pinout is right. They are
good for spacing, connector access and silkscreen legibility, and for nothing
else. The parts still waiting on a human eye are listed in
`checks/config.py`, and none of them can be settled from a picture.

**The copper is not finished.** `board.mk` says `ROUTING := incomplete`: the MCU
core and the power block are routed, everything from the safety chain onward is
placed only, and the outstanding connections are left for M8. A plot of this
board is a plot of work in progress, and will look like one.

**A stale picture is worse than no picture.** These are regenerated by the
target above, not edited. If they disagree with the board file, the board file
is right.
